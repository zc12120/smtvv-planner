# 独立计算节点

默认在部署机器本地计算，不需要外部账号或计算节点。可选用主站调度、独立节点求解的方式。主站设置
`SMTVV_COMPUTE_MODE=remote` 后，最优路线、旧版限定次数路线、快捷规划、
正向合体和逆向配方查询均进入远程队列；没有本机搜索降级。页面、登录、
请求格式校验、队列、状态查询和缓存由主站负责。

以下示例使用两个自有节点，各运行两个 Supervisor 工作进程，合计四个计算位置。
每个进程通过经过 TLS 验证的 HTTPS 长轮询领取任务，有空位即领取下一份，
单任务不会等待凑成一批。连接复用，空闲领取最长等待 5 秒，运行时每 4 秒心跳。
Python 建图、C++ 求解和规则回放验证全部发生在节点内。

## 调度和缓存

- 主站 `/state/compute-queue.sqlite3` 使用 SQLite WAL，保存任务、客户端请求、
  心跳、结果及旧接口分页进度。应用重启后任务继续保留。
- 最多 64 个不同的排队／运行任务、2,048 个客户端请求记录。
- 条件先规范化：技能、材料限制、DLC、排除与未解锁集合的顺序不影响任务标识。
  数据、规则与计算实现的摘要参与版本标识；不同版本的节点不能领取任务。
- 相同条件的正在执行任务只计算一次，每位用户取得独立请求编号。
  一人取消不会取消其他人的请求；全部订阅者取消才停止实际任务。
  每位用户的技能展示顺序独立保留。
- 完成结果最多保留 24 小时、512 项、128 MiB；单项最大 8 MiB。
  已有缓存或相同在途任务不受不同任务的队列容量限制。
  完成请求记录保留约 30 分钟；错误结果不作为成功缓存复用。
- 工作节点的租约为 30 秒。心跳丢失后重新分配，最多分配 3 次；旧租约提交被拒绝。
  完成结果提交可幂等重试。执行预算为 180 秒，排队超过 15 分钟后给出重试提示。
- 节点网络中断时会在租约可能重新分配前中止当前求解。每项任务运行在独立进程组，
  取消、超时或异常退出时回收 C++ 子进程；Linux 父进程死亡信号防止留下孤立求解器。
- 两个节点均不可用时请求排队或提示重试，主站不会接手求解。

旧版 `/api/routes/*` 不被当前前端使用。其首批两种排序结果在节点生成并缓存；
后续按页的兼容请求在节点重新执行限定次数搜索，再复用中央分页缓存。
这条兼容路径不如当前 `/api/optimal/*` 高效，主站也不会承担它的计算。

## 部署配置

主站在状态卷内配置权限受限的 `compute-workers.json`，每个节点拥有独立随机令牌，
主站仅保存 SHA-256 摘要。示例中的占位符必须由真实随机令牌摘要替换：

```json
{
  "worker-a": {"slots": 2, "tokenSha256": "<64-character SHA-256>"},
  "worker-b": {"slots": 2, "tokenSha256": "<64-character SHA-256>"}
}
```

主站环境变量：

```text
SMTVV_COMPUTE_MODE=remote
SMTVV_STATE_DIR=/state
SMTVV_WORKERS_FILE=/state/compute-workers.json
```

节点使用专用非特权用户 `smtvv-compute`。程序目录为
`/opt/smtvv-compute/releases/<revision>`，`current` 链接指向当前版本。
`/etc/smtvv-compute.json` 为 root 与服务组可读的 0640 文件，包含
`url`（主站 HTTPS 地址）、`worker`（节点名）和 `token`（该节点令牌）。
不要将这些运行配置加入 Git。

Supervisor 配置见 [compute-supervisor.conf](../deploy/compute-supervisor.conf)。
Python 3.10+ 可直接运行节点代码；上线时先编译 `native/optimal.cpp` 并写入
`native/optimal-linux.sha256`。日常运行不编译、不安装 Docker，日志每个位置最多
保留三份 5 MiB 文件。两个位置均设置 nice=5，空闲 CPU 可以充分使用，原有业务保留。
每个任务的 Python 地址空间限额为 768 MiB，原生求解器为 512 MiB。

仅 `/api/compute/worker` 使用独立工作节点鉴权；该入口在接收大请求体前验证令牌，
不依赖浏览器 Cookie、Origin 或登录状态。外层和应用网关仅对这一个路径允许 9 MiB
请求体，其他 API 继续使用原大小限制、浏览器鉴权和计算限速。
节点只向主站发起连接，没有公开的计算监听端口。

更新时先在隔离候选服务检查同版本的两个节点，再更新主站镜像、配置和该精确路径。
主站和节点都必须拥有匹配的代码与规则数据。已有生产应用的源站保护、CDN、
账户、会话与验证码设置继续有效。

## 监控和回滚

后台计算队列显示每个节点的在线位置数和正在执行的真实任务数。
`supervisorctl status smtvv-compute:*` 可检查节点进程；日志位于
`/var/log/smtvv-compute/`。主站数据库可以只读查询任务的 worker、slot、attempts
和状态，用于确认是否发生重试，不能通过编辑数据库手动复制运行租约。

代码回滚需要将主站镜像和节点代码一起切回匹配版本。保留当前状态卷，旧版本仍在途
任务会收到“规则已更新”的提示；不要用旧快照覆盖账户和登录设置。
如果明确回退到原来的单机部署，还需恢复原 `.env`、Compose、网关和源站工作节点
专用路径，并停止两个计算节点；这属于回滚操作，不是运行时自动降级。

所选云服务商对实例关停、回收和重建的规则不由应用控制；应用已覆盖网络中断、进程
退出和主站重启恢复，实例被平台永久回收仍需重新安装程序和节点凭据。
