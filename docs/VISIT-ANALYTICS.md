# 后台访问统计

管理后台的「访问统计」提供页面访问、独立 IP、浏览器访客、生成路线次数、每日趋势、热门页面、地区、来源、设备、浏览器、IP 筛选、页面筛选、翻页、访问详情和 CSV 导出。

页面和站内导航通过同源 `POST /api/analytics/collect` 上报；可见时长在隐藏/离开时更新。只允许攻略页路径，查询参数只保留资料名称/栏目，来源仅保留域名。Cookie、密码、配置分享链接、请求正文、完整来源路径不记录。计数反映收到的浏览器事件；拦截脚本、断网、机器人伪造、共享 IP、清理本地标识均会影响统计，不能用于安全审计或精确人数判定。User-Agent 可查看，界面全部转义，CSV 防止公式执行。

主站只缓存最多 5,000 个待传事件和最多 4 个管理查询，不在主站落盘。每个来源 IP 每分钟最多接收 120 个事件。缓冲满后跳过新事件并累计遗漏数；长时间断联或主站重启可能丢失未传事件，后台显示连接状态、待接收数和遗漏数。该取舍用于保持主站低开销。

统计节点使用独立随机令牌，经 HTTPS 主动长轮询 `/api/analytics/worker`，每批最多 200 个事件。只有事务提交后才确认接收，重传以事件/访问 ID 去重。查询由管理员鉴权后转交同一节点，最多等待 15 秒。计算节点、健康检查、静态图片请求和后台访问都不进入访客库。

节点逐个回复管理查询，单次回复限制 7 MiB；结果过大会返回查询错误，可缩小查询范围后重试，防止多个 CSV 同时导出导致通信反复失败。

## 玻尔1部署

- 程序、地区库及数据库默认放在 `/personal/smtvv-analytics/` 的持久目录。代码与计算 worker 分开，由独立 Supervisor program 运行。
- 数据库：`/personal/smtvv-analytics/data/visits.sqlite3`；每天滚动删除超过 60 天的访问和行为记录。汇总也仅统计这 60 天，不另留长期个人访问历史。
- `/personal` 是网络文件系统，所以节点只有一个进程/数据库连接，使用 SQLite DELETE journal，不使用需要共享内存的 WAL；按批写入，索引查询，摘要缓存 30 秒。
- 程序使用系统 Python 标准库；地区库 reader 来源为固定版本 ip2region，运行时不调用外部 IP 查询 API。IPv4/IPv6 各缓存 512 KiB 索引，并限制 IP 查询结果缓存为 4,096 项。
- 节点配置为私有 JSON：`url`（HTTPS 主站源）、`token`、`database`、`geoDirectory`。启动时把地区目录加入 `PYTHONPATH`。
- 主站状态卷中的 `analytics.json` 只有 `tokenSha256` 和随机 `salt`。未放置该文件时采集默认关闭。令牌和访客数据库禁止提交 Git。
- 源站和网关需为 `/api/analytics/worker` 单独配置最多 9 MiB、至少 25 秒超时、`no-store`、按节点令牌认证的 POST 路径。采集接口沿用本站 Origin、真实 IP 和业务鉴权。

可通过 `python3 scripts/install_analytics_geo.py /personal/smtvv-analytics/geo` 下载固定上游版本；数据库约 46 MiB，reader 和数据许可保留在同目录。公开数据不定期更新，升级时调整固定提交后重新下载并重启统计节点。数据来源：https://github.com/lionsoul2014/ip2region ，固定提交 `f8b0792b0cd729f5b2593f690aeed225e49c1967`。

## 使用

后台默认查询最近 7 天，提供今天/7/30/60 天；时间按北京时间划分。「浏览器访客」为随机本地标识加盐后的值；不使用浏览器指纹。点击 IP 可以筛选该地址的历史访问，详情显示可见停留、设备和计算操作。CSV 每次最多导出 5,000 条，超过时可按时间/条件收窄或从更早记录页继续导出。

## 界面约定

沿用现有后台石色底、青玉色操作和刻金编号；访问概览→趋势→排名→筛选→访问明细。IP 使用数字字体，页面以仲魔/技能名称呈现，数据表单行紧凑、手机允许横向滚动。统计只在该区域可见时按分钟刷新，管理设置的原有刷新不触发统计查询。

常规报表由本地按需构建的 Apache ECharts 6.1.0 提供，只有管理员滚动到访问统计后才加载；前台访客不下载图表运行时。不增加 Node/数据库常驻服务，地区和历史库仍在玻尔1。图表使用 SVG renderer，9个实例在刷新/主题/宽度变化时复用，页面离开销毁，关闭绘图动画。标准提示框在SVG内绘制，来源等用户字符串不解释成HTML。

- 六项概览：页面访问PV、浏览器访客UV、独立IP、会话、平均页面可见停留、生成路线；每会话页数按页面访问/会话计算。
- 流量趋势：今天按北京时间小时，7/30/60天按天；PV/UV/IP同坐标，折线/柱状切换、交互图例、悬停明细、键盘日期及长区间缩放。
- 页面、来源、地区：横向条形排行，最多前8项，显示覆盖所选访问量的占比；点击页面条形可筛选访问明细。
- 设备、浏览器、系统：环形图和计数/比例图例；分类前8项以外归入「其他（未列出）」，比例按页面访问计算。
- 时段分析：24小时累计柱状图、星期×小时168格热力图，均使用北京时间；累计次数不解释为日均，也不推断未采集的历史。

新增汇总只在玻尔1查询SQLite现有数据，不做架构/表迁移；按已有时间/IP/路径条件筛选，再汇总每小时、星期时段及操作系统。摘要继续缓存30秒，后台可见时每分钟刷新。UV为本项目浏览器随机标识去重，口径并不等同Umami等平台；暂不展示不能从现有数据准确确定的在线人数/营销转化。

调色沿用石白/墨青表面、青玉主色与旧金辅助色，添加成组的蓝/紫/玫瑰统计色；4px间距，现有标题/正文/数值字体。`scripts/analytics-charts.mjs`列出Line/Bar/Pie/Heatmap和所需组件，`npm run build:analytics`可复现本地包，`npm run build:web`同时重建图标与所有资源版本。上游许可在`web/admin/vendor/ECHARTS-LICENSE.txt`，依赖版本与完整性固定在package-lock。完整平台方案对比见ECharts按需构建、[Umami部署](https://docs.umami.is/docs/install)及[Matomo部署](https://matomo.org/faq/on-premise/matomo-requirements/)；当前使用现有采集/存储加浏览器图表，避免引入额外常驻平台。

主站内存并非零开销：有界转发队列、HTTPS 长轮询、管理查询回复和 Python 线程会使用内存；仅不保存访客历史数据库。评估占用时分别看容器内存、系统匿名内存和可回收文件缓存，不能把整机曲线的变化全部归到该功能。构建/读取发布文件也会增加缓存，优先看 `MemAvailable`。

## 验证与恢复

`python3 -m unittest discover -s tests -p test_visit_analytics.py` 覆盖接口权限、路径过滤、缓冲上限、认证、节点查询、事件去重、分页和 60 天清理。浏览器验收见 `tests/analytics_browser.cjs`，必须使用隔离测试实例。

主站回滚到旧发布不影响已存玻尔1的数据。统计节点故障时计算节点继续运行；恢复独立统计 Supervisor program 即可。备份数据库应通过 SQLite backup API 生成一致性快照；不要直接覆盖运行中的数据库。诊断日志按 2 MiB×3 滚动，只记录服务连接和程序错误，访客明细保存在数据库内。
